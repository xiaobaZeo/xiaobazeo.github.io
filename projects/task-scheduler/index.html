项目案例

分布式任务调度中心

基于 gRPC 的任务分发、心跳检测与弹性算力协调，支撑日均 100 万+ 算法任务。

2024.07 — 至今

资源利用率提升 50%

  • gRPC
  • Redis
  • 任务调度
  • 弹性扩缩容

背景与痛点

算法任务运行时间远高于预期，节点内部瓶颈难以定位；任务负载与计算资源分配不匹配，造成热点倾斜与资源浪费。

处理链路

  1. 任务接入

    统一记录任务、执行状态与调度需求。

  2. 调度与分发

    结合任务优先级与节点负载分配任务，通过 gRPC 双向流连接计算节点。

  3. 执行与心跳

    回传任务进度与实例心跳，观察运行状态。

  4. 资源与复盘

    根据任务积压动态调整资源，以性能日志定位执行瓶颈。

关键设计

统一调度链路

建设任务状态管理与分发能力，结合 gRPC 双向流、任务分发策略和心跳检测协调算法实例。

负载驱动的弹性资源

根据任务积压与机器负载调整算力，减少热点倾斜和低负载时的资源闲置。

以运行记录支持优化

沉淀算法执行性能日志与任务复盘机制，为性能优化和资源规划提供依据。

结果

  • 支撑日均 100 万+ 算法任务调度。
  • 资源利用率提升 50%。
  • 已公开的调度优化结果：DB 查询量下降 95%+。
