项目案例

AI Agent 工作流协作平台

多阶段会话、标准化工具接入、Kubernetes 环境隔离与 SSE 运行轨迹，让 Agent 执行可编排、可追踪、可恢复。

2026.01 — 至今

Pod 初始化：约 10 秒降至约 3 秒

  • Agent Runtime
  • MCP
  • Kubernetes
  • SSE

背景与痛点

一次性对话难以沉淀为可复用流程，复杂任务需要反复补充上下文；执行过程与容器启动链路缺少统一视图，问题定位成本较高。

处理链路

  1. 任务与上下文

    组织阶段输入、预加载背景和工具能力，为会话准备必要的信息。

  2. 会话与运行环境

    由后端管理 Agent 会话，通过 Kubernetes 准备隔离的执行环境。

  3. 工具与阶段执行

    接入 Agent SDK、MCP 与 Skills，执行工具调用并交接阶段产物。

  4. 轨迹与观测

    通过 SSE 呈现消息、工具调用和任务进度，以 Trace / Perf 分析关键阶段耗时。

关键设计

统一能力接入

将工具接入、上下文注入与产物交接组织成统一链路，减少不同 Agent 能力接入时的重复工作。

隔离的会话环境

围绕会话级独占 Pod，建设初始化配置注入、归档恢复、空间回收和 Pod 复用能力，兼顾隔离与运行效率。

先观测，再优化

贯通前端、后端与 Pod 的运行阶段，拆解 Agent 启动、SSE 连接、环境初始化和工具执行耗时，以观测结果指导优化。

结果

  • Pod 初始化平均耗时由约 10 秒缩短至约 3 秒。
  • 沉淀 10+ 可复用工作流，服务 70+ 用户。
  • 执行消息、工具调用与阶段进度可实时查看。
