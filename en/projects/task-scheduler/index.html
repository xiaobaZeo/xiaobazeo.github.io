PROJECT CASE STUDY

Distributed Task Scheduler

gRPC task dispatch, heartbeats and elastic compute for 1M+ daily algorithm tasks.

Jul 2024 — Present

50% higher resource utilization

  • gRPC
  • Redis
  • Task scheduling
  • Elastic compute

Background

Algorithm tasks took longer than expected, bottlenecks within compute nodes were hard to diagnose, and resource allocation did not track task load.

Architecture

  1. Task intake

    Record tasks, execution states and scheduling requirements in one place.

  2. Scheduling & dispatch

    Allocate tasks using priority and node load, connecting compute nodes over bidirectional gRPC streams.

  3. Execution & heartbeats

    Report progress and instance heartbeats to observe runtime state.

  4. Resources & review

    Adjust compute capacity against backlog and use execution logs to identify bottlenecks.

Key decisions

A unified scheduling path

Coordinate task states and dispatch with bidirectional gRPC, distribution policies and heartbeat detection.

Load-driven resource allocation

Scale compute capacity against backlog and machine load to reduce hot spots and idle resources.

Performance records for optimization

Use execution timing logs and task reviews to support algorithm optimization and resource planning.

Outcomes

  • Supported 1M+ daily algorithm tasks.
  • Improved resource utilization by 50%.
  • Previously disclosed scheduling optimization: 95%+ fewer DB queries.
