PROJECT CASE STUDY

Agent Workflow Platform

Multi-stage agent sessions, standardized tools, Kubernetes runtime isolation and SSE execution traces.

Jan 2026 — Present

Pod initialization: about 10s to 3s

  • Agent Runtime
  • MCP
  • Kubernetes
  • SSE

Background

One-off conversations are difficult to reuse, complex tasks repeatedly need context, and execution and startup stages need a coherent view for diagnosis.

Architecture

  1. Task & context

    Prepare stage inputs, relevant background and the tools needed for each session.

  2. Session & runtime

    Manage agent sessions on the backend and provision isolated execution environments with Kubernetes.

  3. Tools & stages

    Connect Agent SDK, MCP and Skills, run tools and hand off stage artifacts.

  4. Traces & visibility

    Stream messages, tool calls and progress over SSE; analyze stage timings through Trace / Perf.

Key decisions

Standardized capability integration

Organize tool access, context injection and artifact handoff into one consistent integration path.

Session-level isolation

Build around dedicated session Pods with configuration injection, archive recovery, workspace reclamation and Pod reuse.

Observe before optimizing

Connect frontend, backend and Pod stages to understand agent startup, SSE connection, environment initialization and tool execution timings.

Outcomes

  • Reduced average Pod initialization from about 10 seconds to about 3 seconds.
  • Supported 10+ reusable workflows serving 70+ users.
  • Made execution messages, tool calls and stage progress visible in real time.
